`agent-browser run` executes a JavaScript program that drives the browser. The script can loop, branch, and pass data between steps, then return only the final value. An agent that would otherwise spend one turn and one snapshot per command finishes a multi-step task in one call, with far less output to read.

## Running a script

```bash
# Inline
agent-browser run -e 'await open("https://example.com"); return title()'

# From a file
agent-browser run scrape.js --timeout 300000

# From stdin
agent-browser run <<'JS'
await open("https://example.com/search");
fill("input[name=q]", "agent-browser");
press("Enter");
wait({ text: "results" });
return evalPage(`[...document.querySelectorAll("h3")].map(h => h.textContent)`);
JS
```

Global flags such as `--session`, `--profile`, and `--auto-connect` apply as usual. Top-level `await` and `return` work, and the returned value is the result. An uncaught error exits with status 1.

## How it works

The script runs in an embedded QuickJS sandbox inside the CLI process. Every `ab(...argv)` call runs an ordinary CLI command through the same parser, policies, and session as `batch`, so domain allowlists, action policies, and confirmations still apply. The helper functions below are thin wrappers over `ab()`.

## Examples

Act on refs without a model turn:

```bash
agent-browser run <<'JS'
await open("https://example.com/settings");
const { refs } = snapshot({ interactive: true });
const boxes = Object.entries(refs).filter(([, r]) => r.role === "checkbox");
for (const [ref] of boxes) check("@" + ref);
return boxes.map(([, r]) => r.name);
JS
```

Paginate and collect:

```bash
agent-browser run <<'JS'
await open("https://example.com/items");
const items = [];
for (let page = 0; page < 20; page++) {
  items.push(...evalPage(`[...document.querySelectorAll(".item")].map(e => e.textContent.trim())`));
  if (!isVisible("button.next")) break;
  click("button.next");
  wait({ load: "domcontentloaded" });
}
return items;
JS
```

Use a site skill:

```bash
agent-browser run <<'JS'
const gh = skills.load("github");
return gh.listPullRequests("vercel-labs/agent-browser", { limit: 5 });
JS
```

See [Skills](/skills) for the available site helpers. Helpers that change anything only draft unless called with `{ confirm: true }`.

Failed commands throw `AbError`. Catch it to fall back, or let it propagate. Run-level error codes in `--json` output:

## Sandbox limits

- No filesystem, network, process, `require`, or module access. The browser is reachable only through `ab()` and the helpers.
- A memory limit applies, and the `--timeout` deadline interrupts runaway code.
- `run`, `batch`, `chat`, `mcp`, `dashboard`, `install`, and `upgrade` cannot be called from a script.
- Each run starts with a fresh scope. Use `store` to carry data between runs.
- Snapshots are [redacted](/snapshots#secret-redaction) by default; pass `snapshot({ noRedact: true })` to opt out.

## MCP

The `agent_browser_run` tool is part of the default `core` profile. It takes `code` (required) and an optional `scriptTimeoutMs`, plus the common arguments such as `session` and `timeoutMs`. The server instructions recommend it for any task with more than one or two steps.

## When to use it

Use code mode once you know what to do: form fills, pagination, loops over rows, extraction across several pages. Use plain commands for a single quick action, or when you need to see an unfamiliar page before deciding what to do.
